# חוזה הקטלוג (`schema: 1`)

הקטלוג הוא קבצי JSON סטטיים שה-CI בונה ומפרסם בענף `data`. התוסף רק קורא אותם. זה
החוזה היחיד בין `catalog/` ל-`plugin/`: שינוי בו מחייב לעדכן את שני הצדדים, ואם הוא
שובר תאימות גם את `schema`.

כתובת הבסיס: `https://raw.githubusercontent.com/mmichaelush/otzaria-alonim-plugin/data/`.

## קבצים

| קובץ | תוכן | מתי נטען |
|------|------|----------|
| `manifest.json` | גרסה, מקורות ובריאותם, רשימת השרדים עם גיבוב | תמיד ראשון, ובכל סנכרון |
| `series.json` | כל הסדרות | אחרי המניפסט, כשהגיבוב השתנה |
| `weeks.json` | שבתות, פרשות, חגים ומועדים, משנה אחת אחורה ועד שנה קדימה | אחרי המניפסט |
| `weeks-archive.json` | אותו מבנה, לשנים הישנות יותר (מהשנה הראשונה שיש בה לפחות 20 גיליונות מתוארכים); אופציונלי, `files.weeksArchive` | לפי בקשה |
| `recent.json` | הגיליונות של "השבוע": 3 שבתות אחורה ושבת אחת קדימה, עד ~1.5MB (ראו להלן) | ציור ראשון, לפני כל שרד אחר |
| `issues/<hy>.json` | גיליונות של שנה עברית (`5787`), מפוצלים ל-`<hy>-<k>` כשחוצים 3MiB (3,145,728 בייט) | ברקע, או לפי בקשה |
| `issues/timeless.json` | חומר בלי שנה ופרשה (זמירות, תפילות, חוברות) | ברקע |

**כללי כתיבה:** UTF-8, בלי BOM, מפתחות ממוינים, שדה `null` או ריק מושמט, מערכים
ממוינים יציבה (אותו קלט, אותו פלט, בייט בבייט). כך ה-commit בענף `data` ריק כשלא
השתנה דבר.

## `manifest.json`

```json
{
  "schema": 1,
  "catalogVersion": 1791834000,
  "generatedAt": "2026-10-15T07:40:00Z",
  "minPluginVersion": "0.1.0",
  "sources": [
    {
      "id": "ladaat",
      "name": "לדעת",
      "url": "https://ladaat.co/gilyonot/",
      "mode": "catalog",
      "status": "ok",
      "checkedAt": "2026-10-15T07:39:00Z",
      "lastOkAt": "2026-10-15T07:39:00Z",
      "issueCount": 2345,
      "note": ""
    }
  ],
  "files": {
    "series":  { "path": "series.json",  "sha256": "…", "bytes": 91234, "count": 1180 },
    "weeks":   { "path": "weeks.json",   "sha256": "…", "bytes": 8000 },
    "recent":  { "path": "recent.json",  "sha256": "…", "bytes": 230000, "count": 640 }
  },
  "shards": [
    { "id": "5787", "path": "issues/5787.json", "sha256": "…", "bytes": 1200000,
      "count": 3100, "from": "2026-09-12", "to": "2026-10-24", "addedMax": "2026-10-14T20:03:05Z" }
  ]
}
```

- `catalogVersion`: שניות Unix של הבנייה. עולה בלבד. התוסף מדלג על סנכרון כשהוא זהה.
- `sources[].mode`: `catalog` (אנחנו מושכים רשימה) או `link` (אין גישה אוטומטית, רק
  קישור לאתר; כרגע אין מקור כזה).
- `sources[].urlBase`, `sources[].urlTemplates`: ראו "דחיסת URL". אופציונליים; מקור `link` לא נושא אותם.
- `sources[].status`: `ok`, `degraded` (חלק מהפריטים נכשלו), `blocked` (חסום, למשל
  Cloudflare; לא עוקפים), `down`, `disabled`. `note` הוא משפט בעברית למשתמש.
- `sha256` של כל קובץ הוא של התוכן הבינארי כפי שנשמר. התוסף משווה אותו למה ששמר ורק
  אז מוריד מחדש.
- `shards[].from/to`: טווח `date` בשרד (ללא `null`), לדילוג על שרדים כשמסננים לפי תאריך.

## `series.json`

מערך. סדרה היא עלון לאורך שנים, מאוחד בין מקורות.

```json
{
  "id": "s_3fa91c02b1",
  "title": "אסיפת גליונות",
  "aliases": ["אסיפת גליונות - ליקוט"],
  "previousIds": [],
  "lang": "he",
  "circle": "כללי",
  "kind": "weekly",
  "sources": [ { "src": "ladaat", "ext": "37", "title": "אסיפת גליונות" } ],
  "issueCount": 214,
  "first": "2022-09-24",
  "last": "2026-10-17"
}
```

- `id`: `s_` + 10 הקס ראשונים של sha1 של `canonicalKey` (ראו נרמול). יציב בין ריצות.
  כשהמפתח הקנוני משתנה בכוונה, הישן נכנס ל-`previousIds` והתוסף מעביר מועדפים.
- `lang`: `he` `yi` `en` `de` `fr` `es` `ru` `nl` `it` `pt` `fa` `ar` או `other`.
- `circle`: החוג או הקהילה כפי שהמקור מציין (כרגע רק `ladaat` מספק), מחרוזת חופשית.
- `kind`: `weekly` (לפי פרשה) או `timeless`.
- `years` (חדש, אופציונלי): מערך עולה של שנים עבריות שיש בהן גיליונות של הסדרה (לפתיחת שנה בלי לטעון שרדים).
- **שפה היא חלק מזהות הסדרה.** "הבינני" ו"הבינני - אידיש" הן שתי סדרות (`lang` אחד לסדרה): ה-`canonicalKey` של סדרה שאינה עברית הוא `<מפתח>|<lang>`. `title` הוא השם בלי סיומת השפה, ולכן יכולות להיות כמה סדרות באותו `title` ושפות שונות: התוסף מציג את השפה לצד השם.
- סדרה ששמה נגזר מקובץ שלא מזהה סדרה (למשל "עלון נח 9" ב-alonolam) נקראת `<שם> (ללא שם סדרה)` ואינה מתאחדת בין מקורות.
- `aliases`: שמות אחרים של אותה סדרה כפי שהמקורות כותבים אותם. `sources[].ext`: מזהה הסדרה במקור (ladaat: המספר שבסוגריים מרובעים בשם הקובץ, tashma: שם התיקייה, gilyoines: `gilyon_type_id`; alonolam: השם המנורמל, כי אין מזהה).

## `weeks.json`

```json
[ { "date": "2026-10-17", "hy": 5787, "hebrew": "ו׳ בחשוון תשפ״ז", "parasha": ["noach"], "parashaIL": ["noach"],
    "label": "נח", "event": null },
  { "date": "2026-09-21", "hy": 5787, "hebrew": "י׳ בתשרי תשפ״ז", "parasha": [], "parashaIL": [],
    "label": "יום כיפור", "event": "yom-kippur", "shabbat": false } ]
```

שורה אחת לכל שבת, ממוינת עולה. **בנוסף** שורה ליום חג שאינו שבת (`shabbat: false`, `parasha` ו-`parashaIL` ריקים, `event` הוא החג, `date` היום הראשון שלו), כי מקורות מתארכים עלוני חג בתאריך החג עצמו (ladaat: `2026-09-21` = יום כיפור). חג שחל בשבת נושא את ה-`event` בשורת השבת ואין לו שורה נוספת. חנוכה וסוכות/פסח מקבלים שורה ליום הראשון ובנוסף כל שבת שבתוכם נושאת את ה-`event`. `parasha` לחו"ל, `parashaIL` לישראל (שונים בכמה
שבתות בשנה). `event` הוא שבת מיוחדת או חג שיש להציג לצד הפרשה (`rosh-hashana`,
`shabbat-shuva`, `sukkot`, `shemini-atzeret`, `chanukah`, `shabbat-hagadol`,
`shabbat-zachor` וכו'), או `null`. `label` הוא התווית לתצוגה, בעברית, ל"חו"ל" אלא אם
`parashaIL` שונה, ואז `label` נושא את שתיהן ("חוקת־בלק · בלק"). כש-`event` נוסף על פרשה, ה-`label` מסתיים ב-` – <שם האירוע>` ("ויקהל־פקודי – שבת החודש"). הטווח: שנה אחורה ושנה קדימה, מיושר לשבת, כדי שהקובץ לא ישתנה ביום-יום. `parasha`, `parashaIL` ו-`event` נכתבים תמיד בשורת שבוע (גם ריקים/`null`), בניגוד לשאר הקבצים, כי "ריק" ב-`parashaIL` נושא משמעות (שבת חג בחו"ל וקריאה רגילה בארץ).

### חגים ומועדים בשורות השבוע

כל שורה: `date`, `hy`, `hebrew` (תאריך עברי טקסטואלי, "ו׳ בחשוון תשפ״ז"; חדש, אופציונלי לצרכן: אפשר לחשב בתוסף), `parasha`, `parashaIL`, `label`, `event`, ואופציונלית `events` ו-`shabbat:false`.

- `event` הוא האירוע **הראשי** של היום (לפי סדר חשיבות קבוע), או `null`. `events` (חדש, אופציונלי) מופיע כשביום יש אירועים מלבד הראשי (או רק אירוע משני): מערך של כל האירועים. לסינון לפי אירוע: `row.events ?? [row.event]`.
- שורה לכל **שבת**, ובנוסף לכל יום חול שבו **מתחיל** אירוע (היום הראשון של חג/צום/ר״ח; אירוע בן כמה ימים, כמו חנוכה וחול המועד, מקבל שורה ביום הראשון בלבד, והשבתות שבתוכו נושאות את ה-`event` שלו).
- האירועים לפי לוח חו"ל (ההבדלים עם ארץ ישראל הם יום החג השני בלבד, ולכן בשבתות נשמר `parashaIL` נפרד).
- **ערכי `event` (סלאגים קבועים; נוספים ולא משתנים):**
  - ימים נוראים וסוכות: `rosh-hashana`, `tzom-gedaliah`, `shabbat-shuva`, `yom-kippur`, `sukkot`, `chol-hamoed-sukkot`, `hoshana-raba`, `shemini-atzeret`, `simchat-torah`.
  - חנוכה ושבט: `chanukah`, `asara-btevet`, `tu-bishvat`.
  - אדר: `shabbat-shekalim`, `shabbat-zachor`, `taanit-esther`, `purim`, `shushan-purim`, `shabbat-parah`, `shabbat-hachodesh`.
  - פסח עד שבועות: `shabbat-hagadol`, `pesach`, `chol-hamoed-pesach`, `shvii-shel-pesach`, `lag-baomer`, `shavuot`.
  - בין המצרים: `shiva-asar-btammuz`, `shabbat-chazon`, `tisha-bav`, `shabbat-nachamu`; בנוסף `shabbat-shirah`.
  - `rosh-chodesh` (שורה ביום הראשון; ה-`label` נושא את החודש: "ראש חודש חשוון").
  - **משניים** (מופיעים רק ב-`events`, אף פעם לא כ-`event`): `aseret-yemei-teshuva` (ג׳ עד ט׳ בתשרי) ו-`shabbat-mevarchim` (השבת שלפני ראש חודש, חוץ מתשרי).
- `rcMonth` הוא שדה פנימי ואינו נכתב.
- **פרשות במקומות שבהם לא נקראת פרשה** (שבת שהיא חג בחו"ל): `parasha` ריק. שבת שהיא גם ראש חודש נושאת `rosh-chodesh` כ-`event` רק כשאין אירוע חשוב ממנו.

מזהי פרשות (`parasha`): הסלאגים של Hebcal באנגלית באותיות קטנות ומקפים:
`bereshit noach lech-lecha vayera chayei-sara toldot vayetzei vayishlach vayeshev
miketz vayigash vayechi shemot vaera bo beshalach yitro mishpatim terumah tetzaveh
ki-tisa vayakhel pekudei vayikra tzav shemini tazria metzora achrei-mot kedoshim emor
behar bechukotai bamidbar nasso behaalotcha shlach korach chukat balak pinchas matot
masei devarim vaetchanan eikev reeh shoftim ki-teitzei ki-tavo nitzavim vayeilech
haazinu vezot-haberakhah`. בשבת משולבת זה מערך של שתיים.

## גיליון (בשרדים וב-`recent.json`)

```json
{
  "id": "i_8c11d0e47a93",
  "series": "s_3fa91c02b1",
  "title": "אסיפת גליונות",
  "no": 21,
  "date": "2026-10-17",
  "hy": 5787,
  "parasha": ["noach"],
  "event": null,
  "lang": "he",
  "pages": 24,
  "added": "2026-10-14T20:03:05Z",
  "assets": [
    {
      "src": "ladaat",
      "ext": "23569",
      "url": "https://ladaat.co/gilyonot/uploads/2026-10-17/files/[37]-אסיפת-גליונות-נח.pdf",
      "page": "https://ladaat.co/gilyonot/view/23569",
      "thumb": "https://ladaat.co/gilyonot/uploads/2026-10-17/thumbnails/[37]-אסיפת-גליונות-נח.1.png",
      "bytes": 25225710,
      "pages": 24,
      "downloads": 513
    }
  ]
}
```

- `id`: `i_` + 12 הקס של sha1 של `seriesId|hy|שבוע|no`, כש"שבוע" הוא הפרשות (`a+b`), אחרת `event`, אחרת `date`. כששני גיליונות שונים מתנגשים באותו מזהה (אותו שבוע, אותה סדרה, אותו מספר, בלי ודאות לאחד) מתווסף לנוסחה `src:ext` של העותק המוביל. שום דבר שנגזר מהכותרת לא נכנס לנוסחה, כדי שמזהה לא ישתנה כשהניתוח משתפר או כשהקטלוג נקרא מחדש.
- `title`: כותרת לתצוגה לגיליון הזה (ללא פרשה ושנה כשאפשר לחלץ אותן). הכותרת המקורית
  נשמרת ב-`assets[].rawTitle` (ראו להלן). **לא** מוחקים מידע: כל מה שנגזר ניתן לשחזור.
- `date`: תאריך השבת ש**הגיליון שייך לה**, לא תאריך ההעלאה. נגזר מהמקור (תיקיית
  תאריך ב-ladaat, week ב-gilyoines) או מפרשה + שנה (`weeks.json`). `null` כשאין ודאות.
- `hy`: שנה עברית כמספר (5787). `null` רק ב-`timeless`.
- `parasha`: מערך סלאגים (ריק או מושמט אם אין). `event`: ראו `weeks.json`.
- `no`: מספר גיליון/שנה/שבוע כפי שמופיע בכותרת, אם זוהה. `null` אם לא.
- `added`: ISO UTC. הכי מוקדם שהגיליון נראה, או תאריך ההעלאה במקור. משמש ל"חדש".
- `archive` (חדש, אופציונלי, `true` או מושמט): ה-`added` אינו אמין כסימן ל"חדש" (ייבוא המוני או העלאה מאוחרת של חומר ישן). **אין להציג גיליון עם `archive` כ"חדש"**, ואין לכלול אותו ב-`recent.json` אם אין לו תאריך. הכלל (`catalog/lib/archive.mjs`): (1) יש `date` וההעלאה הראשונה היא יותר מ-45 ימים אחרי השבת (בלי תאריך אבל עם שנה: אחרי סוף השנה העברית), או (2) אין `date`, והעלאה הייתה ביום שבו מקור אחד הוסיף 600 קבצים או יותר (נמדד בסריקה מלאה). הדגל נדבק: אחרי שנקבע הוא נשמר. **`added` עצמו אינו משתנה** (זה זמן ההעלאה האמיתי).
- `assets`: לפחות אחד. כל אחד קובץ אחד אצל מקור אחד. הסדר הוא העדפת ברירת מחדל
  (איכות ואמינות מקור), לא סדר זמן.

שדות `asset`: `src` (חובה), `ext` מזהה במקור (חובה), `url` קישור ישיר ל-PDF (חסר אם אין
הורדה אוטומטית), `page` דף הגיליון באתר המקור (**תמיד קיים** בארבעת המקורות ב-`catalog`, גם כש-`url` קיים: התוסף מציג לקריאה, מוריד ומדפיס מ-`url`, ופותח את `page` ב"פתח באתר"; באתרים בלי דף לכל גיליון זה דף האתר או הגלריה), `thumb`, `bytes`,
`pages`, `downloads`, `rawTitle` (כותרת/שם הקובץ כפי שהם במקור), `sha256` (רק אם חושב).

### דחיסת URL בנכסים

המניפסט נושא לכל מקור `urlBase` (כתובת https בסיס, הקידומת הארוכה המשותפת לקבצי ה-PDF והתמונות שלו) ו-`urlTemplates` (`{ url?, page?, thumb? }`, עם `{ext}` כ-placeholder). כללי פענוח של `assets[].url|page|thumb`:

1. שדה **חסר** בנכס ותבנית קיימת לו במקור: ערכו הוא התבנית אחרי החלפת `{ext}` ב-`asset.ext`. הבנייה מכתיבה תבנית לשדה רק אם לכל עותקי המקור יש את השדה, כך ששדה חסר בלי תבנית פירושו "אין".
2. ערך (או תבנית) שמתחיל ב-`https://` הוא מוחלט. אחרת הוא יחסי: `urlBase + ערך` (חיבור מחרוזות). תבנית ריקה (`""`) פירושה `urlBase` עצמו.
3. **תווים לא-ASCII נשמרים מפוענחים** (עברית ישירות, UTF-8); אחוזי-קידוד של ASCII (`%20`, `%5B`, `%26`, `%23`, `%3F`, `%25`) נשארים כמות שהם. לפני שימוש (הורדה, `app.openUrl`, allowlist) מצפינים **רק** תווים לא-ASCII: `encodeURIComponent` לכל תו (נקודת קוד) כזה, בכתיב hex גדול. התוצאה היא בדיוק ה-URL החי.

כל הכללים ממומשים ב-`catalog/lib/urls.mjs` (`resolveAssetUrls(asset, source)`, `encodeNonAscii`, `decodeNonAscii`); וקטורי בדיקה שהתוסף מריץ מול ההעתק שלו: `catalog/test/fixtures/url-vectors.json`. הבנייה בודקת בכל ריצה שכל נכס מתפענח בחזרה בדיוק לערך המקורי. תחיליות ותבניות לכל מקור: `docs/SOURCES.md`.

### ירושה של שדות חוזרים

כדי לצמצם נפח: `issue.lang` חסר = `lang` של הסדרה; `issue.title` חסר = `title` של הסדרה; `assets[].rawTitle` חסר = `title` של הגיליון (אחרי הכלל הקודם). שדה שנכתב מפורשות תמיד גובר. הדוגמאות במסמך זה מציגות את הצורה המלאה; `catalog/test/fixtures/url-vectors.json` (`inherit`) מכיל וקטורי בדיקה. בשרד בנייה מלאה זה חוסך כ-8MB מתוך כ-46MB.

**כפילות בין מקורות:** אותו גיליון בכמה מקורות הוא רשומה אחת עם כמה `assets`. איחוד רק
כשיש ודאות (אותה סדרה, אותה פרשה ואותה שנה, ושם/מספר/גודל שאינם סותרים). כשיש ספק
משאירים שתי רשומות. דיוק לפני כיסוי; איחוד שגוי גרוע מכפילות. אין מחיקה של עותק מקור.

## נרמול (חייב להיות זהה בקטלוג ובתוסף)

`normalizeKey(s)`: NFKC, הסרת ניקוד וטעמים (U+0591–U+05C7), מקף/מקף מפריד/גרשיים/
גרש/מרכאות מכל סוג והלוכסנים הופכים לרווח או נמחקים (לפי הטבלה בקוד), אותיות סופיות
לרגילות, אותיות לטיניות לקטנות, צמצום רווחים. מחזיר מחרוזת להשוואה בלבד, לעולם לא
לתצוגה. מימוש יחיד ב-`catalog/lib/normalize.mjs`, והעתק זהה (עם בדיקת זהות) ב-
`plugin/js/alonim-normalize.js`. `canonicalKey` של סדרה הוא `normalizeKey` של הכותרת
אחרי הסרת מילים כלליות ("עלון", "גליון", "גיליון", "שבועי", "לשבת", "פרשת", מספרים,
שנים, שמות פרשות), ואחרי החלת `catalog/data/aliases.json`.

## יציבות ועקרונות

- **התוסף חייב לעמוד בשדות לא מוכרים** (להתעלם) ובשדה חסר מותר (לא להיכשל).
- שינוי תואם-אחורה (שדה חדש) לא מעלה `schema`. הסרה/שינוי משמעות כן, והתוסף מציג
  "יש גרסה חדשה של התוסף" כש-`schema` גבוה ממה שהוא מכיר, וממשיך עם המטמון.
- כל מקור הוא מחבר נפרד: כשל באחד מסמן אותו ב-`sources[].status` ואינו מפיל את הבנייה.
  שרד שלא נבנה מחדש נשמר מהריצה הקודמת (לא נמחקים נתונים בגלל תקלה זמנית).

## מה שנקבע ביישום (הבהרות לחוזה)

- **`recent.json`:** גיליונות עם `date` מ-3 שבתות אחורה ועד שבת אחת קדימה (שבת = הקרובה, מיושר כך שהקובץ משתנה פעם בשבוע), ובנוסף גיליונות **בלי** `date` ש-`added` שלהם בתוך אותו טווח וש**יש להם עותק שאינו מ-`tashma`** (קבצי tashma בלי תאריך הם חומר ארכיון, לא "השבוע"). אותם אובייקטים בדיוק כמו בשרדים (אותו `id`, אותם כללי ירושה), **אבל בלי `assets[].rawTitle`** (נשאר בשרדים). תקרה קשיחה 1,500,000 בייט: אם חורגים, חותכים לפי סדר החשיבות ההפוך: השבוע הישן ביותר קודם, ובתוך שבוע הגיליונות עם הכי פחות עותקים, ואז לפי `id`. כל מה שנחתך נמצא בשרדים.
- **סדר:** בשרדים וב-`recent.json` הגיליונות ממוינים מהחדש לישן לפי `date` (בלי תאריך בסוף), ואז לפי `id`. סדרות לפי `id`.
- **`manifest.json` לא משתנה כשהתוכן לא השתנה.** כשכל הקבצים והמצב של המקורות זהים לריצה הקודמת, הקובץ נכתב בייט-בבייט כמו קודם (כולל `catalogVersion`, `generatedAt` ו-`checkedAt`), כדי שה-commit בענף `data` יהיה ריק. פעם ב-24 שעות נכתב מניפסט עם חותמות זמן חדשות (heartbeat), ולכן `checkedAt` של מקור יכול לפגר עד יממה אחרי הבדיקה האמיתית.
- **`added`:** תאריך ההעלאה במקור כשיש (ladaat, tashma, gilyoines), ובמקור בלי תאריך (alonolam) מועד הריצה הראשונה שראתה את הקובץ, ונשמר מהריצה הקודמת.
- **גיליון בלי `date` ועם `hy`** (למשל קובץ שנמצא בתיקיית שנה אבל בלי פרשה) נשמר בשרד של אותה שנה; `date` חסר. `hy` חסר = `timeless`.
- **`weeks.json` ו-`event`:** גיליון ששייך לשבת מקבל `parasha` ו-`event` מהלוח, לא מהכותרת (מקור שמתארך בעצמו קובע את השבוע; הלוח קובע מה נקרא בו).
- **`weeks-archive.json`:** שורות לוח של כל השנים שלפני תחילת `weeks.json`, מהשנה הראשונה שיש בה 20 גיליונות מתוארכים לפחות. נועד לניווט ("עבור לפרשה/חג") בשנים ישנות; אפשר לטעון אותו בעצלתיים.
- **סדר הדחיסה והירושה, `archive`, `years`:** ראו הסעיפים הרלוונטיים למעלה.
- **שיעור הוודאות של alonolam** (סדרה/פרשה נגזרות משם הקובץ) נשמר רק פנימית (`rawMeta.confidence`) ואינו חלק מהפלט.
