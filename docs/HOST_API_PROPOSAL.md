# הצעה לאוצריא: קובץ מרוחק בלי הורדה, והדפסה מהצפיין

מסמך עבודה פנימי (לא מיועד לפרסום כמות שהוא). הוא נועד ליישור בין התוסף לבין ה-PR לאוצריא.
הבעיות נמדדו בבדיקה חיה באוצריא 0.9.98 (ראו `docs/ARCHITECTURE.md` §6).

## הבעיות

1. **צפיין PDF בתוך התוסף נחסם.** שרת הקבצים של התוספים שולח `X-Frame-Options: SAMEORIGIN`, ודף
   התוסף הוא `file://`, ולכן `<iframe>` על כתובת הקובץ המקומית נחסם. תיעוד ה-SDK אומר ש-iframe עובד.
   הפתרון הנוכחי בתוסף: `fetch` ← Blob ← `iframe src=blob:` (עובד, אבל מעתיק את הקובץ בזיכרון).
2. **אי אפשר לפתוח קובץ מרוחק בלי לשמור אותו בתיקיית המשתמש.** `network.fetchStream` מחזיר UTF-8
   בלבד, ו-`network.download` כותב לתיקייה שהמשתמש אישר. קריאה בלבד של גיליון מחייבת קובץ קבוע.
3. **אי אפשר להדפיס PDF מהתוסף.** `iframe.contentWindow.print()` נכשל ב-`SecurityError` (מקור שונה),
   ו-`ui.print` מדפיס את דף התוסף ולא את הקובץ.

## ההצעה (שלוש תוספות קטנות, כולן על תשתית קיימת)

1. **קובץ הנגיש לתוסף ב-iframe:** תשובות שרת הקבצים לקבצים שהוענקו לתוסף אינן שולחות `X-Frame-Options`;
   במקומו `Content-Security-Policy: frame-ancestors` עם מקורות התוסף. כך `<iframe src=url>` עובד, כמו
   שהתיעוד כבר טוען.
2. **`network.fetchFile`** (שם סופי לפי המקובל ב-API; הרשאה: `network.access` או `network.localhost`, אותה
   בדיקת allowlist כמו `network.download`):
   ```js
   const { data } = await Otzaria.call('network.fetchFile', { url, timeoutMs?, maxBytes? });
   // data = { token, url, name, size, mime }
   ```
   המארח מוריד לתיקיית מטמון זמנית **פרטית לתוסף** (מכסת LRU של כ-256MB,
   מנוקה בסגירת אוצריא), ומוסר token מסוג קובץ משתמש לקריאה בלבד. כל ממשקי ה-token הקיימים עובדים עליו
   (`fs.resolveFileUrl`, `fs.revokeFile`, `<iframe>`).
3. **`ui.printFile({ token, jobName? })`** ← `{ printed: boolean }`. פותח את **מסך ההדפסה של אוצריא
   עצמה** (אותו `PrintingScreen` שקורא ה-PDF משתמש בו: טווח עמודים, תצוגה מקדימה, פריסה, ובסוף דיאלוג
   ההדפסה של מערכת ההפעלה) על קובץ PDF שה-token שלו שייך לתוסף. ההבטחה נפתרת כשהמשתמש סיים:
   `printed: true` אם נשלח להדפסה, `false` אם ביטל; היא נמשכת כמה שהמשתמש לוקח (בלי פסק זמן בצד
   התוסף). רק PDF. התוסף אינו מניח שהמארח דורש מחוות משתמש טרייה: הוא קורא מיד, ורק אם חזר
   `error.forbidden` הוא מציג כפתור "הדפסה" וקורא שוב בלחיצה (נפילה לאחור למארח שמחמיר).
   הדפסה מרובה היא רצף: מסך הדפסה אחד בכל פעם, והבא נפתח רק אחרי שהמארח החזיר תשובה על הקודם.

כל השלושה זמינים מגרסה 0.9.99 (תאריך הכנסת השדה `spec.json`).

## זיהוי יכולת בתוסף

התוסף קורא לשיטות החדשות רק אחרי בדיקה (גרסה ≥ 0.9.99 מ-`app.getInfo`, ותפיסת `error.unknown_method`/
`error.unsupported`), ונופל לאחור: Blob לקריאה, הורדה לתיקייה, והדפסה דרך סרגל הצפיין או הקורא של אוצריא.
